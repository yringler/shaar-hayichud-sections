# Claude Code Instructions — site

> **Monorepo context**: This is the `site/` sub-project. See the [root CLAUDE.md](../CLAUDE.md) for an overview of the full repo. Everything rendered here comes from the repo's [`data/`](../data/README.md) directory: chapter JSON, which [`section-tool`](../section-tool/CLAUDE.md) edits, and the class catalog.

## Overview

Static site for chapters of Shaar Hayichud with labeled subsections, plus audio class recordings. It also publishes `data/` as versioned JSON at `/data/v1/` for other clients, such as the Flutter app.

## Tech Stack

- **Hugo** — static site generator (Go templates)
- **Yarn 4** (PnP) — package manager (epub script; `yarn build` also installs and runs `../data/tools`)
- **TypeScript** for the browser scripts (`hugo/assets/js/`), bundled by Hugo's built-in `js.Build` (esbuild); type-checked with `../data/tools`' TypeScript. The site's only build dependency is **Pagefind** (pinned, see Search), for the search index

## Commands

```bash

yarn build    # data + Hugo build → hugo/public/ (minified) + yarn search-index
yarn serve    # data + Hugo dev server with live reload (no search index; see Search)
yarn search-index  # compile scripts/search-index.ts (tsc → scripts/build/) and write hugo/public/pagefind/
yarn test     # Unit tests (lib/json-renderer.js, the audio model, search text) + typecheck of hugo/assets/js and scripts/search-index.ts
              #   (typecheck needs ../data/tools installed: yarn data does it)
yarn test:e2e [dir]  # OPT-IN browser test of the audio features on hugo/public (run yarn build
              #   first; needs Playwright with Chromium and ffmpeg): chapter pages, no transcripts anywhere,
              #   class lists (lesson text, reader, topics, Autoplay next), topic deep links,
              #   the outlines pages (all their links checked in the built HTML), the study guide
              #   pages (/study/ and the unlisted /advanced/: noindex, robots, sitemap, no link in;
              #   links, every line/passage/block, no JS), the site nav and search.
              #   Screenshots go to [dir].
              #   Under Yarn PnP Playwright may not resolve: run it as
              #   NODE_PATH=$(npm root -g) node scripts/e2e-audio.cjs [dir]
yarn test:scripts  # Unit tests for scripts/sefaria-swap.py (python3)
yarn epub     # Generate EPUB from ../data/chapters
```

## Deployment

The site is hosted on **Cloudflare Pages**. Every push to the repo triggers an automatic build and deployment using:

These are dashboard settings (Pages project → Settings → Builds); a Pages Wrangler file can't set the build command or root directory, so they don't live in the repo:

- **Root directory**: `site`
- **Build command**: `yarn build`. This runs the data build in `../data/tools`. Pages clones the whole repo, so `../data` is available. Invalid data fails the deploy.
- **Output directory**: `hugo/public`
- `hugo/static/_headers` sets the Pages response headers. `/data/*` and `/texts/*` are CORS-open (`Access-Control-Allow-Origin: *`), `/data/*` is cached for a short time, and `/advanced/*` is `X-Robots-Tag: noindex`. `hugo/static/_redirects` sends the old transcript pages (`/classes/transcripts/*`) to `/classes/`. `hugo/static/robots.txt` disallows `/advanced/` and names the sitemap.

## Module Mounts

`hugo.toml` mounts directories from outside `hugo/`:
- `../../data/chapters` → `data/chapters` (`site.Data.chapters`) and `static/texts` (legacy raw JSON at `/texts/chapter_NN.json`)
- `../../data/dist/v1` → `static/data/v1` (the published JSON API)
- `../../data/dist/v1/catalog.json` → `data/v1` (`site.Data.v1.catalog`, read via the `catalog.html` partial, which fails the build if the data build has not run)
- `../../data/dist/v1` → `assets/data/v1` (audio alignments and outlines, read with `resources.Get … | transform.Unmarshal` by `partials/audio/`; the study guides, by `partials/study/tier.html`). Adding an assets mount replaces the default one, so `assets` → `assets` is listed too.

Per-lecture files in `dist/v1` are named by the decoded lecture ID (`outlines/001 Intro.mp3.json`) while index.json lists the encoded URL path, so templates build asset paths from the ID, never from an index `path`.

Keep mounts portable across Hugo versions: Cloudflare Pages builds with its image's default Hugo (no `HUGO_VERSION` is pinned) while developers may run a much newer one. Mount single files directly instead of filtering a directory (`includeFiles` was removed in Hugo 0.153; its `files` replacement does not exist in older releases). Likewise, stay on `site.Data` until the Pages default Hugo supports `hugo.Data`; newer Hugo only warns about it.

## Content Adapters

Content adapters (`_content.gotmpl`) auto-generate pages from data at build time — no `.md` stub files needed per chapter. When a new chapter JSON is saved via the section-tool, Hugo discovers it automatically on next build.

Each chapter generates 3 pages:
- `/texts/chapter-N/` — English view
- `/he/texts/chapter-N/` — Hebrew view
- `/translation/chapter-N/` — Translation view (only if chapter has translations)

The class catalog generates more:
- `content/classes/_content.gotmpl`: `/classes/<series>/` and `/classes/<series>/<part>/` (see Audio Classes)
- `content/outlines/_content.gotmpl`: `/outlines/<series>/` for each series with at least one published outline (see Outlines pages); `content/outlines/_index.md` is `/outlines/`
- `content/study/_content.gotmpl`: `/study/<study series id>/` and `/study/<study series id>/chapter-N/` for each public study guide (see Study guide pages); `content/study/_index.md` is `/study/`
- `content/advanced/_content.gotmpl`: `/advanced/<study series id>/` and `/advanced/<study series id>/chapter-N/` for each advanced study guide (see Advanced study guide pages); `content/advanced/_index.md` is never rendered and cascades the pages' settings

## Site nav

`layouts/_default/baseof.html`: Home, Texts, Classes, Study, Outlines, Search, About, plus the language switch. Labels come from `data/i18n.json` (`nav.*`, en/he). Study (`מדריך לימוד` in Hebrew), Outlines (`תקצירי שיעורים`) and Search (`חיפוש`) show in both languages and always link the English `/study/`, `/outlines/` and `/search/`. The translation has no nav item: the English Texts page (`layouts/texts/list.html`) starts with an "English translation →" entry linking `/translation/`. The app page (`/app/`, `content/app.md`: store badges, a scroll-snap strip of screenshots served from the media CDN (`app/screenshots/` in the R2 bucket), feature cards; badges in `static/img/badges/`) is deliberately not in the nav: the home pages (en and he) link it in one line under the description (`.app-note`, `i18n.json` `app.*`), and About links it too. Only the site nav (`body > nav`) gets the nav bar styles in `main.css`; other `<nav>` elements (`nav.class-toc`, `nav.part-nav`, `nav.outlines-nav`) style themselves.

## Hugo partials

- `catalog.html`: the class catalog (`site.Data.v1.catalog`), failing the build when the data build has not run.
- `classes-url.html`: the one place that builds class page URLs. `dict "series" $s` → `/classes/<series>/`; with `"part" $p` → `/classes/<series>/<part>/` (slugs: `title | urlize`). `content/classes/_content.gotmpl` creates those pages with its own slugs and must agree with it.
- `audio/lectures.html` (cached): every catalog lecture by ID with its `series`, `seriesUrl`, `part`, `partUrl` (its class page: the part page, or the series page for a lecture directly under the series), `anchor` (`class-<id | urlize>`, the id of its box) and `classUrl` (`partUrl#anchor`). Use these instead of building class links.
- `format-time.html`: seconds → `h:mm:ss` or `m:ss`, the same as `formatTime()` in `assets/js/audio/model.ts`. Every time shown by a template goes through it.
- `audio/outline.html`: a lecture's published topics (`title`, `startSeconds`) or an empty slice. `audio/topics.html`: a class box's collapsed topic list (`details[data-track-topics]`, one `button[data-start]` per topic), used by `class-track.html`.
- `outlines/tree.html`, `outlines/class.html`, `outlines/class-details.html`, `outlines/nav.html`: the outlines pages (below).
- `study/tier.html` (cached per tier), `study/index.html` (the public tier), `study/plan.html`, `study/block.html`, `study/play.html`: the study guide pages (below). `study/tier.html` is the one place that builds study URLs; every link into them from the rest of the site goes through `study/index.html`.

## Directionality

- The site is **LTR English** overall (`<html lang="en">`)
- Hebrew chapter text bodies are wrapped in `<div dir="rtl">`
- Audio/classes pages use `.ltr-content` class

## Content Pipeline

1. Chapter JSON files in `../data/chapters/` are loaded as Hugo data via module mount
2. Content adapters generate pages referencing data keys (e.g., `chapter_01`)
3. `layouts/_default/single.html` checks for `chapter_data` param and calls the recursive `render-textnode.html` partial
4. The partial walks the `TextNode` tree, emitting `<div class="depth-N">` blocks with hierarchical numbering and one `<span class="line">` per line of text
5. Raw JSON files are also served at `/texts/` via the static mount

### JSON TextNode Format

Chapter files are JSON arrays of `TextNode` objects (produced by `section-tool`; schema: `../data/schema/v1/chapter.schema.json`). A section's own text is a run of `Line` objects (`{id, text}`, one line, no newline) at the start of its `children`:

```json
[
  {
    "label": "optional section label",
    "children": [
      { "id": "k3m9qa2x", "text": "a line of Hebrew text" },
      { "label": "child section", "children": ["..."] }
    ],
    "translation": "optional English translation"
  }
]
```

Tell the two apart by `children`: a section always has it, a line never does.

### Transformation Rules

- Each `TextNode` with lines of its own emits a `<div class="depth-N">` block
- Each line is rendered as `<span class="line" id="<line id>">`, wrapped in a `<p>` when the section has several lines. The line ID is the anchor that audio alignments and study guides point at, so every line must keep its span and ID. The EPUB omits the IDs (they may start with a digit, which XHTML forbids).
- `render-textnode.html` and `lib/json-renderer.js` must produce the same markup
- Hierarchical numbering: `1`, `1.1`, `1.1.1`, …
- Optional `label` shown as `.label` inside the div
- Footnote digit markers stripped from Hebrew text content: `replaceRE \d+`
- Child sections recursed into (flat HTML output, not nested divs)
- Translation shown only when page param `showTranslation` is true

## Outlines pages

`/outlines/` (`layouts/outlines/list.html`) introduces the auto-generated topic outlines and has one card per series that has an outlines page: its counts and a link to each of its parts there (`/outlines/<series>/#<part anchor>`).

`/outlines/<series>/` (`layouts/outlines/single.html`, same series slug as `/classes/`) shows the whole series in catalog order, every topic pre-rendered:

- Breadcrumb, `h1` (series title), counts, Expand all / Collapse all (`.outlines-controls`, `data-js-only`).
- Each part is a `section.outline-part` with an `<h2>` and `id="<part title | urlize>"`, and a link to its class page. Each chapter heading in it is a `section.outline-chapter` with an `<h3>` and `id="<part anchor>--<chapter title | urlize>"`, set off by a side border, so the part's loose classes (outside any heading) are visibly not in a chapter.
- Each class with an outline is a collapsed `details.outline-class`: the summary has the title and topic count; inside, an "Open class" link to its box (`classUrl`) and an `<ol class="outline-topics">` of topic deep links, `<partUrl>?t=<int startSeconds>#<box anchor>`, each "`<span>time</span> title`". classes.js on the class page opens that box's topics and offers Play from there (see Class lists). The markup is lean on purpose (the Walters page has about 930 topics): the time span has no class, and only titles with Hebrew letters are wrapped in `<bdi>`.
- `partials/outlines/tree.html` (cached per series) builds the page's model and decides what is shown: parts and chapter headings without any outlined class are left out; a class without an outline in a shown part, loose or inside a shown heading, is listed plainly (title linking to its box, "no outline yet"); lectures directly under the series form a last part, "Other classes" (`#other-classes`). The adapter makes a page only for a series with at least one outline.
- Build failures: two parts or chapters on one page with the same anchor (or an empty one), and a lecture missing from `audio/lectures.html` (its links would have no target).
- Wide screens (≥ 64rem): the body widens to 72rem (`body:has(.outlines-layout)`) for a sticky side nav (`nav.outlines-nav`) listing parts → chapters. Narrow screens hide it and show the same list (`partials/outlines/nav.html`) in a "Jump to" `<details>` at the top.
- `outlines.js` (`assets/js/outlines.ts`): Expand all / Collapse all, and the part crossing the top 30% of the viewport gets `aria-current="location"` in the side nav (IntersectionObserver; the first part until one gets there). It opens nothing on load, also when the URL names a part.

## Study guide pages

The study guides (`data/dist/v1/study/`, always the public edition: see data/README.md, "Publishing tiers") as pre-rendered pages: the public tier here, under `/study/`, the advanced tier under `/advanced/` with the same layouts (see Advanced study guide pages). Pre-rendered and readable without JS: each class is then a plain `<audio preload=none>` and each ▶ a link. With JS, `study.js` (below) replaces those players with one docked player that follows the guide.

- **Source**: `partials/study/tier.html` (cached per tier; context `"public"` or `"advanced"`) reads one index through the `assets/data/v1` mount (`resources.Get | transform.Unmarshal`): `data/v1/study/index.json` (public, root `/study/`) or `data/v1/study/index-advanced.json` (advanced, root `/advanced/`), failing the build when it is missing. It returns the `tier`, `root`, `series` (id, title, teacher, catalogSeriesId, url, chapters), `chapters` (chapter key → one entry per series with a guide: url, number, path, status, stale, lectures, teacher) and `lectures` (catalog lecture id → `{chapter, number, page, url, slug, series}` per guide that cites it; `url` is the guide with `?class=<class slug>`: the id lowercased, extension dropped, other runs of characters → `-`, `classSlug()` in `study-model.ts`). It is the only place that builds study URLs; it fails the build on a series id that is not a plain slug, two pages with one URL, a guide path outside `study/<series>/`, or (advanced) a series that is also in the public index. `partials/study/index.html` returns the public tier: every link-in below uses it, so nothing outside `/advanced/` can link an advanced guide. The layouts pick the tier from `.Params.studyTier` (default public).
- **URLs**: `/study/` (`content/study/_index.md`, html only; `layouts/study/list.html`: one card per series with its chapter chips), `/study/<study series id>/` (the series' guides in book order with title, class count and Draft / Out of date chips; same layout, `.Params.studySeries` set) and `/study/<study series id>/chapter-N/` (`layouts/study/single.html`). The slug is the study series id (`walters-original`), not the catalog title.
- **Guide page** (`single.html`): breadcrumb (no `/study/` root on an advanced page); title; pills to the chapter text (`?teacher=`) and each class page (`audio/lectures.html` `classUrl`); the draft notice ("Machine-drafted from <teacher>’ class and not yet checked against it. The recording is the source.", teacher from the index) and a stale notice; the docked player (`partials/study/player.html`, hidden without JS); a collapsed "Classes on this chapter" list (`#classes`: `li.study-class` with `data-lecture/start/end/label/url` and `data-continues-in`/`data-continues-url` when the class reads on into a chapter with a public guide; each class's label, its part of the chapter, an `<audio controls preload=none data-no-js>` with the catalog URL, links to where it starts and its class page); "Jump to" (narrow) / sticky side nav `nav.study-nav` (≥ 64rem, `body:has(.study-layout)` widens to 72rem) listing the sections; the overview (`#overview`) with its `overviewAudio` ▶ links; then each section (`section.study-section#sec-<first line id>`, `h2` title, summary) and its passages.
- **Passage** (`div.study-passage#s-<first line id>`, `data-lecture/start/end`: its first in-place item's class and that class's time range in it; `.is-skip` for `skip` passages, shown compact with the chapter's text muted and a note): a `div.study-text[lang=he][dir=rtl]` of `div.study-line`s, each with the section number where it changes and `span.line#<line id>[data-line]` (`data-line` on every rendering, the `id` once) holding the passage's phrases that start on that line (`span.phrase` with `data-lecture/start/end` when translated, `.is-untranslated` otherwise; `span.phrase-he` with footnote digits stripped like chapter pages, `span.phrase-en[lang=en][dir=ltr]`; two columns from 48rem). Each line id is rendered as an `id` once (a repeated or unknown id of a stale guide is not; an unknown line of a `skip` passage is left out). Then the blocks.
- **Blocks** (`partials/study/block.html`): `div.study-block.kind-<kind>#b-<first line id>-<n>` (`n` from 1 within the passage; these move when a guide is edited, line ids do not) with `data-kind`, `data-lecture`, `data-start`, `data-end` (the first `audio` entry) and `data-out-of-place="1"` (and `data-tellings`, JSON of its further `audio` entries, when it has any). The export's `outOfPlace` string is a writer's note and is never shown: an outOfPlace block is labelled "From <class label> · m:ss" ("Said at m:ss" under its own class divider; `span.study-from`, `partials/study/from.html`), computed from its audio, and its ▶ then shows the time only. A head with the kind's tag (none for explanation; keyPoint "Key point", emphasised; mashal / story / digression with their title; avodah "In practice"; question with who asked it, then the question in italics; aside and recap muted) and the ▶ (`partials/study/play.html`): a link to the catalog recording at `#t=<start>` (Media Fragments: works without JS), naming the class when it is not the class of the divider above (`.is-other-class`). A `join: true` block is spliced into the previous block's last paragraph as an inline `span.study-block.study-join` with the same data attributes and its own ▶ (its further paragraphs follow it).
- **Class dividers** (`p.study-divider#c-<class slug>`, unique in the guide or the build fails, `partials/study/plan.html`): where each class starts, counting in-place items only (timed phrases, blocks without `outOfPlace`): before the passage when that is the passage's first in-place item, else before the class's first in-place block in it, else before the next passage. A class with none (the Q and A tapes) has no divider.
- **Prose**: goldmark via `.RenderString` (block display for overview, summaries and block text; inline for phrase `en` and questions). Safe because the data build rejects HTML, links, lists and headings in prose. Phrase `he` never goes through Markdown (some start with `- `).
- **Public edition only** (defence in depth): `single.html` fails the build if any block has `sensitivity` or the guide's series/chapter disagree with the index; the e2e asserts that no published guide has `sensitivity`, that `study-beta` appears nowhere, and that `markel-advanced` appears only under `/advanced/` and its data.
- **Links in** (all through `study/index.html`): the site nav; chapter pages (`_default/single.html`, en and he: a "Study guide: <teacher>" line per series with a guide, above the text); class boxes (`class-track.html`: a "Study guide" pill in `.track-links`, where the transcript pill used to be, or "Study guide:" + one pill per chapter for a class in two guides, `…/chapter-N/?class=<slug>`); outlines (a "Study guide for Chapter N" line under a chapter heading whose classes are in a guide, and a pill beside Open class); `/texts` and `/he/texts` (a "Guide" badge, `i18n.json` `study.*`); the chapter player's "Study guide →" pill (see Audio on chapter pages); search results (one record per passage, see Search).
- **Player and follow** (`study.js`, `assets/js/study.ts`, built by `audio/scripts.html`, loaded only by `single.html`): it reads the guide back from the page (passages, `.phrase` and `.study-block` `data-*`, `li.study-class` parts) into the `StudyPassage[]` of the timing model below, unhides the bar and hides the `data-no-js` class players. **The bar** (`section.listen.study-player[data-study-player]`: its own attribute, so play.js never attaches; the chapter panel's `.listen` look and docking, `.is-active` + `--listen-h` on the same terms, copied from play.ts): Class selector (the chapter's lectures in index order; switching while playing plays the new class from its part's start, else arms `seekOnPlay()` there), ⏮15 / the native `<audio controls>` / 15⏭, "Now: <section title>" (or "the start of the class, before this chapter", "not in the guide", "past this chapter in the class", "aside on another passage · Go to"), Follow (`aria-pressed`; the shared `shaarHayichud.audio.followAlong`, `FOLLOW_KEY` in `audio/store.ts`; unset means on here, off on chapter pages), Autoplay next (the shared setting; `nextStudyPart()`, from 0:00; after the last class "That was the last class on this chapter." and a "Next: Chapter N’s guide →" link when the series has a guide of the next chapter, `data-next-url`; in `after` with `continuesIn`, "This class goes on in Chapter N’s guide →"), "⏮ From start of class (m:ss earlier)" for `studySeekTarget()`'s `offerStartSeconds` (gone 30 s past the tap). It docks on the first play. Never autoplays. **Current items** (on every `timeupdate`/`seeked`/`play`, whether or not Follow is on): the block gets `is-discussing` + `aria-current` (side border filled by progress, `--p` from `itemProgress()`, static under reduced motion; a faint background), the phrase `is-discussing` + `aria-current` (a tint; `Mark` in forced colours). A seek of the script's own is not shown until it lands (`playAt()` starts at the old position while it waits for the metadata). A visually hidden `aria-live=polite` region (`[data-study-live]`) says "Now: <section>" on section changes only. While playing (`playing` or `gap`) the fragment is `lines[0]` of the position (the phrase's line, else the passage's first line) via `replaceHash()`. **Scrolling** (only the page, only while playing with Follow on and attached, only in `playing`, never in the 5 s after a reader scroll: `scrollWatcher(window, '[data-study-player]')`): when the current block changes (or the followed passage does) and it is not on screen (`mostlyOff`: at most a sliver at an edge of the area above the bar), its top goes 25% down the visible area; a phrase 30% (`scrollTopFor()`); only items of the passage `followPassage()` follows (5 s hold; a seek or class change follows at once); an outOfPlace block within ±1 passage is scrolled to, a farther one never ("Now: aside on another passage" with a Go to button). A block taller than the visible area keeps its progress point about 40% down, moving at most every 4 s. Reduced motion: no smooth scroll. **Detach**: a scroll that is not the script's own (`autoUntil`) and leaves the current item (phrase, else block) wholly off screen detaches follow; highlights go on, the page stays put, and `button.study-back-now` floats above the bar ("↑/↓ Back to now · <phrase English, or block kind: title>", only while playing with Follow on). It re-attaches on the pill (scrolls there and focuses the block, `tabindex=-1`), when the item is back in view, on any ▶ or phrase tap, the native play, or a Follow toggle. **Taps**: a phrase (selection-safe: ignored with a selection or on a double-click, 250 ms wait) plays from it, and each block's ▶ (the no-JS link, a plain click only: a modified click still opens the recording) from the block, both through `studySeekTarget()` with the lecture in the player winning when it has the element; a divider's or the overview's ▶ plays that class from its time. Every seek goes through `playAt()`. **Arrival** (`parseStudyLink()`; like topic deep links): `?class=<class slug>&t=<s>` selects the class (`partForSlug()`) and the item `studyAt(t)` names (phrase, else block, else passage); `#<line id>`, `#s-…` and `#b-…` select where that element plays from (`studySeekTarget(…, null)`; a line by its first phrase); the item gets `is-selected` (the `:target` tint), is scrolled 25% down, and a focused `button.audio-link.deep-play.study-deep-play` "▶ Play from m:ss" goes before its block or at the top of its passage, with `seekOnPlay()` for the native play (again after `load`, whose fragment scroll moves focus). `?class=` alone selects the class and shows its divider (`#c-<slug>`). `class` and `t` are then dropped (`replaceState`, fragment kept). An unknown class is ignored.
- **CSS** (`main.css`, "Study guides"): phone first; the bar's controls fit 390px (the class label visually hidden there); print hides the nav, players, the pill, ▶ links and navigation, opens `<details>`, and keeps blocks and phrases unbroken.
- **Timing model** (`assets/js/audio/study-model.ts`, pure, no DOM; vectors in `lib/study-model.vectors.json`). It uses the guide's own times only (phrase `start`/`end`, block `audio`), never the line alignments, which time where the Hebrew is read rather than where the teacher translates and explains. Its input is the guide minimally (`StudyPassage[]`: `lines`, `phrases` `{lines, en?, lecture?, start?, end?}`, `blocks` `{audio, outOfPlace?}`, optional `key`s, default `"i"`, `"i.pj"`, `"i.bj"`), which `guidePassages()` takes from the JSON and the controller can build from `data-*` attributes. `studyTimeline(passages, lecture, part)` indexes one lecture's items sorted by start (array order is never time order) into `spans()` from `audio/model.ts`: blocks by their main telling (`audio[0]`), held `BLOCK_HOLD_SECONDS` (= `HOLD_SECONDS`, 30); further tellings (`audio[1..]`) in a separate list, current only when no main telling is; phrases with English and a time, held `PHRASE_HOLD_SECONDS` (5). `studyAt(timeline, t)` gives `state` (`before`: before the part's `start` or the first item; `playing`; `gap`: nothing current after the hold; `after`: at or past the part's `end` with nothing being said, with `continuesIn`), `phrase`, `block` (of equal starts the first not outOfPlace; `blocks` lists them all), `telling`, `outOfPlace`, `passage` (the phrase's, else the block's, else the last item started's, in `before` the first item's), `readTo` (the passage's last timed phrase started, the reading cursor; Hebrew-only phrases are never named) and `lines` (the phrase's, else the passage's: for `replaceHash()`). `followPassage(state, position, t)` is the scroll target's hysteresis: a different passage is followed once it has been current `PASSAGE_HOLD_SECONDS` (5); gaps and `after` never change it; an outOfPlace block alone (no phrase) more than one passage away is never followed (`shouldScrollTo()`: ±1); pass `null` after a seek or class change to follow at once. Over the 159 public Walters lectures sampled every 5 s it changes passage 630 times, 3 of them backwards. `studySeekTarget(passages, parts, {passage, phrase?, block?}, playerLecture)` is "play from here": the lecture in the player when it has the element, else (passage) the first lecture in `study/index.json` order that teaches it in place, from its earliest item there, (phrase) its start, a Hebrew-only phrase from the last timed phrase before it, (block) its main telling; at a lecture's first item the `playStart()` lead-in rule applies (under `INTRO_SNAP_SECONDS` before it, play from the part's start; longer, offer it as `offerStartSeconds`). `nextStudyPart(parts, lecture)` is Autoplay next within the chapter (index order). `studyLinkHref(guide, lecture, t)` builds `?class=<slug>[&t=<whole s>]` (the chapter player's pill), `itemProgress()` the block's `--p`, `scrollTopFor()` the scroll targets. `parseStudyLink(search, hash)` reads arrival links: `classSlug` from `?class=` (a class slug: `classSlug()`, the same rule as `partials/study/tier.html`, and as the former transcript pages, so old links still work; `partForSlug()` finds the lecture), `t` in whole seconds (`parseDeepLink()`'s rule), `line` when the fragment is a line id (`[a-z2-7]{8}`) and `anchor` (any fragment, decoded).

The advanced tier (`data/v1/study/index-advanced.json`: series whose `series.json` has `advanced`, today `markel-advanced`) is published unlisted, in the same public edition and with the same layouts and `study.js` as `/study/`:

## Search

`/search/` (`content/search/_index.md`, `layouts/search/list.html`, `search.js` from `assets/js/search.ts`) searches a [Pagefind](https://pagefind.app) index that `yarn build` writes to `hugo/public/pagefind/` after Hugo (`yarn search-index`). There is no server: Pagefind's `pagefind.js` loads only the index chunks and result fragments a query needs (about 70–200 KB per search).

- **What is indexed**: the search page writes `/search/manifest.json` (the chapter and translation pages, every class with a published outline with its part page and box anchor from `audio/lectures.html`, and every public study guide from `study/index.html`: page, guide JSON path, chapter, teacher and catalog series title). `scripts/search-index.ts` reads it, takes the text from the published copies in the same output (`texts/<chapter>.json`, `data/v1/outlines/`, `data/v1/study/`), so search covers exactly what is published, adds Pagefind custom records and deletes the manifest. Transcripts are not published, so not searched; the advanced guides are never in the manifest, and the indexer fails on a record linking `/advanced/`. `yarn serve` has no index: the page says search is unavailable.
- **Records**: one per chapter section with lines of its own, one per translated section, one per class outline, one per public study guide passage (740 today; parts: the Hebrew of its lines from `texts/<chapter>.json`, its phrases' English, each block's title, question and text, Markdown emphasis dropped, all linking `<guide>#s-<first line id>`, where study.js puts "▶ Play from"; kind `study`, shown as "Study guide" with the section title, `dir=auto` snippets). Only the public index is read. Each record's `meta.parts` is JSON `[[href, time, text], …]` (a line `<chapter page>#<line id>`, a topic deep link `<part page>?t=<int>#<anchor>`, a passage `<guide>#s-<first line id>`); `search.ts` links and shows the first part with a marked word. Grouping keeps the file count down: Pagefind writes one fragment file per record, and Cloudflare Pages allows 20,000 files per deployment (the site is about 7,950 with the index, the study passages included; per block would be about 3,300 more for Walters alone). Filters: `in` (`Text` / `Classes` / `Study guides`) and `teacher` (catalog series title, also on study passages); the page's "Search in" select maps to them (`study` → Study guides) (`s<series id>` options, one per series with an outline or a public guide, carry `data-teacher`), and `?q=&in=` are kept in the URL (`replaceState`).
- **Pagefind is pinned to 1.4.0.** 1.5 also searches every meta field, which would match the stored display text and the URLs in `meta.parts` (a class's slug would find all its records). Check that before upgrading.
- **Hebrew** (`assets/js/search/text.ts`, shared by indexer and page; unit tested): `foldWord()` drops quotes, gershayim/geresh (`אבי"ע`, `אבי''ע`, `אבי״ע` all → `אביע`), niqqud and edge punctuation and lowercases. A record's content is its folded words followed by extra tokens: each Hebrew word without up to three prefix letters (`ו ה ב כ ל מ ש ד`, at least two letters left), so `חכמה` finds `ובחכמה`, and the canonical token (the entry's first Hebrew form) of every glossary term in it. `analyzeQuery()` rewrites glossary forms in the query, also behind prefix letters, to their canonical tokens, so `chochmah`, `חכמת` and `בחכמה` search `חכמה`, and `ממלא וסובב` works although Pagefind needs every query word in a record. Display text is never folded: `matcher()` and `snippet()` mark the matching words in the original.
- **Glossary** (`assets/js/search/glossary.ts`): key terms with their Hebrew spellings and Latin transliterations. Keep the first Hebrew form one word where possible, and leave out transliterations that are ordinary English words (`or`).
- **Arriving from a result**: `.line:target` gets a highlight; a topic result is a topic deep link (see Class lists); a passage result gets "▶ Play from" (study.js). Never autoplays.
- Pagefind's own fallback: a query word that is in no record matches the longest indexed word it starts with, so a nonsense word can return a few loose results.

## Audio Classes

- The source is `../data/classes.txt`. The data build turns it into `catalog.json`, a tree of series → sections → lectures with stable IDs and one canonical `url` per lecture. Hugo never parses `classes.txt` itself.
- `content/classes/_content.gotmpl` creates one page per series and one page per child section, with slugs built from the titles. Series that have been renamed keep their old URLs as aliases.
- Templates use the lecture `url` exactly as given and never build URLs themselves.
- Each track links to the chapter it is aligned to ("Follow in the text"), when that is published, and to its public study guide, if any. A class aligned to two chapters links to both ("Follow in the text:", "Chapter 34", "Chapter 35"), and both chapter pages list it; `audio/index.html`'s `aligned` entry carries the chapter with the most aligned lines plus `all`. Transcripts are not published or linked (the old `/classes/transcripts/<slug>/` pages redirect to `/classes/`).

**Class lists** (`classes/single.html`, `classes/list.html`):

- A part page has previous/next cards (`partials/part-nav.html`, `nav.part-nav`, `rel=prev`/`rel=next`) under its heading and again at the end: the neighbouring part pages of the same series in catalog order (section items only; lectures directly under a series have no part page). The first part has only Next, the last only Previous.
- A part page with more than one heading starts with a quick contents list (`nav.class-toc`): one pill link per heading (`#<title | urlize>`, the `section.chapter-section` id) with its class count; two headings with the same anchor, or an empty one, fail the build. Each track box has `id="class-<lecture id | urlize>"`.
- Each aligned class shows the chapter text it reads (`partials/audio/lesson-text.html`): every line from its first aligned line to its last in reading order (`audio/chapter-lines.html` → `audio/flatten-lines.html`, numbered like `render-textnode.html`), per chapter it reads, with `data-start`/`data-end` from the class's own alignment (`alignments/<id>.json`) on aligned lines. The lines carry `data-line`, never `id` (a line can appear in several boxes). The box (`.lesson-text`, `dir=rtl`) is about three phrases tall and scrolls on its own.
- `classes.js` (`assets/js/classes.ts`, built by `audio/scripts.html`): one class plays at a time; preview lines get a ▶ button and clicking one (or the line text, selection-safe) plays from there; while the class plays, the current line gets `is-discussing` and the box scrolls itself (never the page; quiet 5 s after the reader scrolls it). "Follow in the text" (`a[data-lesson-open]`) opens the in-page reader instead of navigating: a full-screen `role=dialog` that shows the chapter text taken from the chapter page (`[data-aligned-text]`, fetched once per chapter), lines outside the lesson muted, ▶ and click-to-seek on the lesson's aligned lines, the current line marked and kept in view. The class's own `<audio>` stays where it is in the DOM and is docked by CSS together with its Autoplay next toggle (their wrapper, `.track.is-reading .track-player`, `position: fixed`), so playback is never interrupted. While it is open everything but the reader and the docked player is `inert`, so focus stays in the dialog and the player. Opening pushes a history entry (a page loaded on such an entry clears it); ← Back to classes (once, even on a double-click), Esc or the browser's Back close it and return focus to the link (focused again in a 0 ms timeout: with a `#class-…` fragment in the URL, Chromium's history traversal moves focus to the body right after `popstate`). A chapter page that fails to load is fetched again on the next open. A modified click (new tab) still goes to the chapter page.
- Every seek goes through `playAt(audio, t)` (`audio/player.ts`, shared with play.ts): it waits for `loadedmetadata` when the `<audio>` is not loaded yet (`preload=none`) and keeps at most one pending seek per `<audio>` (a WeakMap), so a later `playAt()` cancels an earlier one that is still waiting; it resolves false when the browser refuses to play. `seekOnPlay(audio, t)` arms a seek for the next native play, also cancelled by any `playAt()`. `smoothScroll()` and `scrollWatcher()` (the 5 s quiet after the reader scrolls) live there too; follow.ts uses them as well (its bundle gets its own copy, fine for these stateless helpers, but it cannot see play.js's pending seeks: a transcript paragraph click sets `currentTime` directly).
- **Topic deep links**: `<part page>?t=<T>#class-<lecture id | urlize>` (`T` = the topic's `startSeconds` floored). On arrival classes.ts (`initDeepLinks()`, after `initAutoplay()` unhides the `[data-js-only]` topic lists) opens the box's topics; with `?t` and topics it selects the last topic whose floored start is ≤ `t`, else the first (`deepLinkTarget()` in `audio/model.ts`; `parseDeepLink()` reads the URL), marks its `<li>` `aria-current` + `is-selected` (kept until another topic is under way), and puts a focused `button.audio-link.deep-play` "▶ Play from m:ss" under the player. It plays from the topic's exact start when `t` names it or is past the last topic's start (the class may be shorter than `t`), else from `t`; the native play button seeks there too on its first play (`seekOnPlay()`). `t` is then dropped from the URL (`history.replaceState(history.state, '', …)`, hash kept). The box is scrolled into view again (`.track` has `scroll-margin-block-start`), and once more after `load`, since the browser's own fragment navigation then moves focus to the body. Never autoplays. Without `?t`, or on a `hashchange` to a `#class-…` box, it only opens the topics and scrolls.
- **Playing line in the URL**: while a lesson plays, the URL's fragment is its current line id (`/classes/…/#<line id>`), written with `replaceHash()` (`audio/player.ts`: `history.replaceState(history.state, …)`, so no history entry, no scroll, no `hashchange`; a no-op when unchanged). It is rewritten on every update, not only on a line change, because closing the reader goes back to the entry before it, whose fragment is older. It stays when playback pauses or ends. Arriving with (or a `hashchange` to) a fragment that is not a `class-…` box (`hashId()` in `audio/model.ts` decodes it), `initDeepLinks()` looks for the first lesson box whose class aligns that line, scrolls it into view with its lesson text at the line, and on arrival adds the focused "▶ Play from m:ss" button (and `seekOnPlay()`) as a topic deep link does. Never autoplays.
- **Autoplay next**: a checkbox under each box's `<audio>` (`[data-autoplay-next]`, `data-js-only`), shown only while that box's class plays (`.track.is-playing`, kept by `markPlaying()` in `audio/store.ts`). When on and a class ends, the next box on the page (document order, across headings) plays from the start. If the reader is open on the class that ended, it swaps to the next lesson (`swap()`: same history entry, its player docked), or closes when that class has no lesson text (focus moves to that box). A class hidden behind the reader never autoplays (opening the reader pauses every other class), and when the browser refuses to start the next class (autoplay policy) the reader closes and the box is shown so it can be started by hand. Closing the reader after a swap brings the focused link on screen. Otherwise the next box is scrolled into view (`block: nearest`, smooth unless reduced motion) unless the reader scrolled the page in the last 5 s (scrolling inside a lesson text box or the reader does not count). The page's last class just stops.

## Audio on chapter pages

Published audio data comes from `../data/audio-publish.json` (see data/README.md, "Publishing audio"). Coverage is sparse on purpose: a chapter with no published alignment renders exactly as before (no player, no script, no `data-t`).

`partials/audio/index.html` (cached) lists what was published: per-chapter alignment indexes, aligned lectures and outlines. `partials/audio/lectures.html` (cached) maps every catalog lecture ID to its series, part and part page.

**Chapter page** (`_default/single.html`, any page that shows the Hebrew): when `alignments/chapters/<key>.json` exists,

- `partials/audio/chapter-panel.html` renders `<section class="listen" data-listen data-chapter-alignments=… data-follow-src=…>` with the Teacher (series) and Class selectors (`[data-listen-series]`, `[data-listen-select]`, options carry `data-series`, `data-url`), the Follow along button (`[data-follow-along]`), one `<audio data-listen-audio preload=none>`, the Autoplay next toggle and a "Study guide →" pill (`a.listen-study[data-listen-study]`, below), a status note (`[data-listen-note]`), and the outline UI (`[data-listen-now]`, `<details data-listen-topics>`). `data-js-only` elements start `hidden`; `data-no-js` ones are hidden by the script. Without JS it is a plain player for the first class.
- Every aligned line gets `data-t="<seconds>"` (best class start: highest confidence, then catalog order); `render-textnode.html` and `lib/json-renderer.js` (`lineTimes` option) stay in parity. The text wrapper gets `data-aligned-text`.
- `play.js` (`assets/js/play.ts`, loaded as a module only on these pages) fetches the chapter alignment JSON, adds a `<button class="line-play">` (no text content, so copying is unchanged) before each aligned `.line`, and plays at once (there is no menu) the best class from the line. **The chosen class first** (the one in the Class selector, which is always the class in the player; `playableRefs()` / `lineInClass()` in `audio/model.ts`): a line it reads always plays it, whatever the teacher preference. A line it doesn't read still plays (the best other class, by the rule below), but its button is marked: `.is-other-class` (a hollow, dashed ring) with the title "Not in “<class>”: plays another class"; clicking it plays that other class (which becomes the chosen one) and the note says "This line is not in “<class>”; playing <teacher>: <class>." The marks update whenever the class changes (`updateLineStates()`). Among other classes: the saved teacher's series first (Rabbi Benyamin Walters Original Class, series `0`, when nothing is saved: `chooseSeries()` in `audio/model.ts`), then the class already playing, then confidence, then catalog order. A `?teacher=` URL parameter overrides the saved teacher for that page load only: play.ts keeps the teacher with its source (`query` or `selected`); a `query` teacher is never saved, and picking a teacher in the selector saves it and drops the parameter from the URL (`history.replaceState`). The value is the series id or its `teacherKey()` (`audio/model.ts`: the title with everything but ASCII letters and digits dropped, `RabbiMarkelSeriesAdvanced`), case-insensitive, or a unique prefix of it (`RabbiMarkel`): `resolveTeacher()`. A linked teacher with no classes on the chapter falls back with a note. The "Follow in the text" links (class lists) carry `?teacher=<teacherKey of the class's series>`; Hugo computes the key with the same regex. The teacher choice is saved in `localStorage` (`shaarHayichud.audio.series`) and applies on every chapter page; if the saved teacher has no classes on the chapter or the line, the page falls back to another series and says so in the note. Every `localStorage` access goes through `readStore()`/`writeStore()` (`audio/store.ts`, try/catch): with storage blocked the page works and choices last for the page only.
- **Intros ("From start of class")**: a line button plays from where `playStart()` (`audio/model.ts`, shared vectors) says. On a class's first line on the chapter, a lead-in under 15 s before it (from the lecture's `chapterStartSeconds`: 0, or where its part on a later chapter starts) is played; a longer one (an intro) is offered: the line plays and `button.listen-from-start` (`[data-listen-from-start]`, under Autoplay next) shows "⏮ From start of class (1:03 earlier)" ("…of this chapter in the class" for a later chapter's part). Clicking it seeks there. It goes once playback is past the line's range (at least 10 s after it), in another class, or after another line tap. Every other line plays from itself. Autoplay next plays the next class from 0:00, so continuous listening hears every intro.
- **Playing line in the URL**: while the panel's `<audio>` plays, the fragment is the current line id of the class in the player (`/texts/chapter-7/#wospio7l`; `spanAt()` over the class's spans, as Follow along uses, but whether or not Follow along is on), written with `replaceHash()` (`audio/player.ts`, replaceState: no history entry). It stays when playback pauses or ends, so a reload or a copied link lands on that line (the line's `id`, by the browser's own fragment scroll).
- **Study guide →**: the panel carries `data-study-guides` (catalog series id → `{url, lectures}` of that series' public guide of the chapter, from `study/index.html`). play.ts (`syncStudy()`) shows the pill only for the teacher of the class in the player when that series has one, and points it at the class (`?class=<class slug>`, `studyLinkHref()`; the guide alone for a class the guide does not cite) and, once the player has played, the moment (`&t=<floor(currentTime)>`, updated on `timeupdate`/`seeked`/`pause`, kept when paused). The guide page then marks that moment with "▶ Play from" (never autoplays). It sits after the Autoplay next toggle, at its line's end while playing, so the docked bar gets no taller; without JS it links the first class's teacher's guide.
- **Autoplay next**: a small checkbox directly under the panel's `<audio>` (`[data-autoplay-next]`, `data-js-only`), shown only while the player plays (`.listen.is-playing`, `markPlaying()`). When on and the class in the player ends, the next class of the same teacher on the chapter (`nextInSeries()` in `audio/model.ts`: the next option in the Class selector) plays from the start through the same path as the selector, so Follow along and the outline follow; the note says "Playing next: <title>". After the teacher's last class on the chapter it stops and says so (no navigation). Its on/off is one setting for chapter pages and class lists (`shaarHayichud.audio.autoplayNext`, `on`/`off`, default off; `autoplayNext()` in `audio/store.ts` keeps every toggle on the page in step).
- Follow in the text and Study guide links (panel, class lists) are pill buttons (`a.audio-link`).
- The panel docks to the bottom once playback starts (`.listen.is-active`, `position: fixed`). play.ts keeps its height in `--listen-h` (ResizeObserver), which sets the body's bottom padding and the lines' `scroll-margin-block-end`, so the last lines stay reachable however tall the panel gets. The docked panel is a flex column, at most 85vh.
- **Follow along** loads `follow.js` (`assets/js/follow.ts`) with a dynamic `import()`. Its on/off is saved in `localStorage` (`shaarHayichud.audio.followAlong`, `on`/`off`); a chapter page loaded with it on turns it on again (without starting playback). While it is on (`html.is-following`), clicking a line's text also plays (selection-safe: ignored when text is selected or on double-click), and the line under discussion gets `is-discussing`; CSS draws `border-inline-start` on its block (`p` or `.content`) via `:has()`. A line is current from its start until the next aligned line of that class starts, held at most 30 s past its own end (`spans()` in `audio/model.ts`): this copes with zero-length ranges and collapsed timestamps. The current line scrolls into view unless the reader scrolled the page in the last 5 s (scrolling inside the panel does not count). With an outline, the panel shows "Now: <topic>" and a collapsible, clickable topic list for the class in the player (marked auto-generated; topics follow the class timeline, not lines).

Scripts are built by `partials/audio/scripts.html` (`js.Build`, ESM, ES2020, minified, fingerprinted). js.Build exists in every Hugo build since 0.74 (no extended edition or Node needed), so it works with Cloudflare Pages' default Hugo (0.147.7 in the v3 image); tested with 0.147.7 and 0.152.2. Hugo writes `assets/jsconfig.json` on each build (git-ignored).
